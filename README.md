# 小兮码生成器

本项目基于 **蓝落萧** 于 2017 年在兮码官方 QQ 群发布的兮码生成器进行修改。

经过对比验证，原版生成器生成的单字拆分规则与 [rime-xxm](https://github.com/rimeinn/rime-xxm/tree/020b3640a01b7eec1347e48bb9efada3e10e000b) 完全一致。

两者仅在词组拆分以及单字未取最优简码等方面存在少量差异。

这是个不错的消息，意味着无需修复那些复杂的拆分规则。

毕竟，小兮码本身就是以主单为核心的输入方案。

## 修改内容

进一步对比词组后发现，原版生成器将单字与词组分开计算，导致单字在分配简码时无法考虑词组的占位情况，单字与词组之间也无法统一竞争最优简码。

因此，我对原版程序进行了简单修改，使其更符合实际码表的生成需求。

### `zpcl.py`

用于生成 `info_new.txt`。

* 将 `z`、`a`、`e`、`o` 等相关声母映射统一调整为 `ri` 方案中的对应规则。
* 输出结果直接按照字频从高到低排序，无需再借助外部工具手动排序。

---

原版似乎需要通过外部工具对生成结果进行排序，修改后输出结果会直接按照字频排序。

为了弄清楚两个 `info_new` 文件之间的差异(其一来自压缩包本身打包，其二由 zpcl 生成)，让我又白白花费了一些时间进行对比，最终才敢确定两者的区别仅仅在于排序方式。

### `sc.py`

用于合成最终码表配置。

* 移除整句配置。
* 直接输出单字与词组合并后的配置文件。

经过再次对比，**目前修改后的生成配置中，所有单字均与 [rime-xxm](https://github.com/rimeinn/rime-xxm/tree/020b3640a01b7eec1347e48bb9efada3e10e000b) 完全一致，差异仅存在于词组部分。**

**还是那句话，这并无大碍。**

**你完全可以通过该项目搭配其他词库生成新的小兮码配置，也可以完全采用纯单字方案，更何况这本来就是主单方案。**
